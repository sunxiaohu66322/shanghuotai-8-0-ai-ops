## 四、运行时与任务机制的真实状况

| 项 | 实测 |
|:--|:--|
| 并发 | `run_batch` / `run_edit` 用 `ThreadPoolExecutor(max_workers=4/2)`，**单次上限 200 件** |
| 日志 | 每次批量操作落 `data/tasks.jsonl`，含 op/mode/value/dry_run/total/ok/fail + **逐件错误原文**（rid 都在，可追踪）|
| 失败隔离 | 逐件 try/except，单件失败不影响其他 |
| **任务中心** | **只是流水账，不是队列**。app.py 里 `暂停/重试/resume/retry/pause/queue` 出现次数 = **0**。任务一旦提交就跑到底，不能中断、不能续跑、不能重试 |
| 幂等性 | `set` 幂等；`add/sub/percent` 重跑会叠加 —— 已靠「先预览」拦，UI 层无强制 |
| 崩溃恢复 | 无。进程被杀，正在跑的任务直接丢，`tasks.jsonl` 里会留下半条记录 |
