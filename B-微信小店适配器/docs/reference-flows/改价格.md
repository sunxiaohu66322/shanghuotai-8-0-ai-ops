## 1. 本地实现与官方接口

本地走 `POST /api/batch {ids, op:'price', mode:'set|add|sub|percent', value, dry_run}`，`do_price()` 逐 SKU 算新价后提交官方 `/channels/ec/product/update`。

**单位口径**：官方 `sale_price` 是**分（int）**，UI 与 CSV 传的是**元**。

## 2. 本轮实测撞到的三个真问题（全部已修）

| # | 问题 | 根因 | 后果 | 修法 |
|:--|:--|:--|:--|:--|
| A | **预览与执行校验不同源** | dry 分支只做 `int(float(value))`，没做负数校验 | 预览显示「将按 set=66 调整」放行，真执行报「价格不能为负」——预览失去意义 | dry 分支改用与 `do_price` 同一套校验；负数/非数字直接拒绝 |
| B | **预览把 66.60 截成 66** | 预览复用 `int()` | 一次预览少 6 毛，按 SKU 数放大 | 价格预览显示**元**并保留小数：`价格 [739.0, 789.0, 959.0] → [66.6, 66.6, 66.6] 元（set=66.6）` |
| C | **兜底没走整对象** | `do_price` 只补全 SKU 字段就重传 | 撞 `6600016 类目错误`（与 `do_stock` 同源，上一轮只修了 do_stock，这里漏改） | 兜底改为在完整 `edit_product` 上就地换 `sale_price` 后整本回传 |
| D | **日志写「6660→6660」** | 就地覆盖 `sale_price` **之后**才读原值 | 操作员无法判断到底写没写对（典型「显示成功但证据自欺」） | 覆盖前先存 `before0` |

## 3. 端到端验收（真写入 + 独立读回 + 还原）

测试品 `10001792717065`（本轮自建草稿，12 SKU，非在售）

```
BASE   [73900, 78900, 95900, 73900] 分   sum 923800
dry   set 66.60  → 预览：12 个 SKU，价格 [739.0, 789.0, 959.0] → [66.6, …] 元（set=66.6）｜未上架商品走整对象更新
real  set 66.60  → 已提交 12 个 SKU 新价（整对象模式，73900→6660）
      读回        → [6660, 6660, 6660, 6660]      ✅ 66.60 元 = 6660 分
real  add 10     → 已提交 12 个 SKU 新价（整对象模式，6660→7660）
      读回        → [7660, 7660, 7660, 7660]      ✅
dry   库存小数    → 拒「库存必须是整数：5.5」      ✅ 校验与执行同源
dry   价格负      → 拒「价格不能为负（sub=-3.0）」  ✅
还原  逐 SKU 原值 → 读回 sum 923800，与 BASE 逐位一致 True
```

## 4. 等级与差距

本地 **L4**（端到端通过：写入生效 + 独立读回 + 逐位还原 + 校验同源 + 失败可追踪到 rid）。未到 L5：**未上架草稿用 percent 模式、0 元、极大值**未穷举；**未在售上架商品上验证过**（快速接口与整对象通路只在草稿品上跑通）。

与原版差距：① 无 17 项筛选（本地只有状态+关键词）② 无行内逐 SKU 编辑与「撤销」③ 无批量粘贴商品 ID ④ 无「修改后价格不低于 X」保护项。
