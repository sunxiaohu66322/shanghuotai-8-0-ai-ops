## 二、它是怎么连上你店铺的（关键结论）

前端 `getApiPath()` 会把 `shipinhao.taosoft.com.cn` 变成 `shipinhao-api.taosoft.com.cn`，
**所有业务调用都发到它自己的服务器**；微信的 `access_token`、商品读写、图片上传全部在它服务器上完成。

它是微信开放平台的**第三方服务商（ISV）**，走 `authorizer_access_token` 代你调用，权限集见官方：
服务市场 `serviceId=3814345211616854019`（小猪批量修改）、`3695234408610267141`（悟空上货）。

**所以「改小猪」这件事做不到**：它的后端在它服务器上；你能改的只有前端 9.8 MB 压缩代码，
而前端只是壳，改完它的后端照样不认。

**但也不需要改**：你有自己的 AppID/AppSecret（商家自研），可以直连官方，功能和它平级，还少一层授权。

### 3.4 真实的几个细节（实证）

| 观察到 | 含义 |
|:--|:--|
| `/shop/relate/rAuthCode.get` 返回 `{"rAuthCode":"598776F1…"}` | 「店铺授权码」= 它的跨店复制凭据，**不是微信的东西**，是他们自家体系 |
| 商品复制页原文：`复制抖音数据包商品时，填写对方的数据包分享码（SJB 开头）` | 它同时做抖店，跨平台搬运 |
| 任务列表里有「申请类目（1885个）：成功 1557 失败 4 已跳过 324」 | 他们的强项是**批量/长任务队列**，不是单件操作 |
| 任务「导入创建商品」参数：是否跳过重复货号/重复标题、是否上架=草稿箱、限购类型、货号保持 | 这些**正是官方 `product/add` 的字段**，说明它只是把官方字段包了一层 |
| 前端 `localStorage` 键：`SHOP_INFO / MEMBER_LIST / PLATFORM_CONFIG / ADDRESS_LIST / APP_INFO / SIZE_CHART_LIST` | 本地只缓存字典类数据，商品数据不落前端 |

## 四、能复用 / 不能复用

| 项 | 结论 |
|:--|:--|
| 它的后端接口 | **不能复用**：要它的 token、它的设备号、它的服务商授权。硬接 = 蹭别人系统，且随时断 |
| 它的前端 UI | **可以借鉴**（信息架构、字段分组、批量交互），已在本项目按此布局 |
| 它的功能清单 | **已完整抄下**（见 `功能地图.md`），作为我们逐项对齐的清单 |
| 它的业务能力本身 | **可以自己实现**：全部落到微信官方接口，你用自己的 AppID 即可，见对照表 |
