# 05 · 路线裁决（已作废）：Excel 导入路线 **停止推进**

> 裁决日期：2026-11-02
> 依据：`01`–`04` 四份文档 + 主会话在真页面上的实测（`v8/publish.mjs`，1436 商品 3 色 × 2 尺寸 = 6 行生成成功）

---

## 一、结论

**Excel 导入路线不是「浏览器路线的备选」，它是另一条需要额外基础设施的产品。放弃。**

**主线回到浏览器自动化（`v8/publish.mjs`）。**

---

## 二、三条独立理由（任何一条单独成立就够否决）

### 理由 1 · 图片是本地文件，Excel 不吃

| | 浏览器路线 | Excel 路线 |
|:--|:--|:--|
| 图片从哪来 | `input[type=file]` 直传本地 `G:\...jpg` | 必须是**公网可抓的 URL** |
| 需要什么 | 无 | **一个图床 / OSS / 网盘直链**，且不能防盗链 |
| 现状 | 已跑通，18 张一次传入 | 一张都传不了 |

样本里 `D3/E3/F3/N3/O3` 全是 `https://1832850322.v.123pan.cn/...` —— 一个本地路径都没有。
我们的图全在 `taobao-picker\data\v3\images\`。

**这一条不是「待确认」，是架构性缺口**：要跑 Excel 路线，得先搭一套图床并保证 URL 长期稳定。
为了绕开一个已经能用的上传框，去搭一套图床 —— 不成立。

### 理由 2 · Excel 会丢掉规格维度名，浏览器不会

实测对比（同一个 1436 商品）：

```
浏览器：第一组规格类型 = 颜色   → 表头 = 颜色 | 价格 | 现货库存
        第二组规格类型 = 尺寸   → 表头 = 颜色 | 尺寸 | 价格 | 现货库存 | ...
        → 买家看到「颜色：胡桃色」「尺寸：长40」

Excel ：模板 16 列里没有一列装维度名，只有 规格1/规格2/规格3 三个位置槽
        → 导入后维度名由平台猜（见 04 ①）
        → 最坏显示成「规格1：胡桃色」
```

**04 的第 ① 条（优先级最高那条）在浏览器路线上根本不存在。**
因为浏览器路线是**显式设置规格类型**的，维度名是我们亲手填进去的。

### 理由 3 · Excel 引入三个新未知，浏览器一个都没有

| 未知 | 浏览器路线 |
|:--|:--|
| 官方模板长什么样（04 ③） | 不需要模板 |
| `商品ID` 填什么（04 ④） | 不需要 |
| 库存 0 收不收（04 ⑦） | 页面上直接填，页面怎么校验就怎么校验 |

**用一条已验证的路，去换一条有 3 个阻断未知的路 —— 方向错了。**

## 三、副产品仍然有效（不浪费）

`01-模板结构.md` 里的两条硬发现，**对浏览器路线照样有用**：

1. **`SKU规格名称` = 各槽取值用空格拼接** —— 印证了浏览器路线上「规格名由平台自动生成」的行为。
2. **一个 SKU 一行、商品级字段只写首行** —— 这是抖店的数据模型事实，和走哪条路无关。

`to_excel.py` 保留，**当且仅当**以下两种情况才启用：
- 将来要做「批量改价 / 批量改库存」的增量更新（这类场景图片不是必需）；
- 用户自己拿到了官方模板并决定走 Excel。

## 五、官方模板还要不要拿

**不拿。** 拿它只能回答「Excel 能不能用」，而 Excel 已经被理由 1 否决了。
拿它的唯一价值是「验证 01 文档的列结构猜得对不对」—— 那是学术问题，不影响上货。

若将来真要做批量改价（第三节第 1 种情况），那时再拿，十分钟的事。
