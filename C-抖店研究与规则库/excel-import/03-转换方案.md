## 1. 字段映射表（我们的字段 → 模板列）

数据源：`抖店研究/crawl3/plan-1436.json`（17 个键：`pid title category_hint main detail video skus price stock cat brand wood install ship_days ship_reason meta missing`）

| 模板列 | 我们的来源 | 转换规则 | 状态 |
|:--|:--|:--|:--|

| `商品详情图` (O) | `detail`（13 张） | `','.join(URL)` 单格拼接，只写首行 | ✅ 样本 16 张可过，13 张没问题 |

| `install='不提供上门安装'` | 塞进 `商品属性`，键名自拟 |

## 2. 多规格拆解算法（本任务的核心）

### 2.1 输入长什么样（实测，6 条）

```
0  新品限时特卖【2026款实木藤编茶边几】              ← 没有颜色、没有尺寸
1  527【实木-可移动-翻盖可调节】胡桃色（长40）
2  527【实木-可移动-翻盖可调节】白色（长40）
3  528【实木-可移动-翻盖可调节】胡桃色（长60）
4  528【实木-可移动-翻盖可调节】白色（长60）
5  528【实木-可移动-翻盖可调节】黑色（长60）
```

注意 `spec` 字段是**长度 1 的数组**，整串名字都在 `spec[0]` —— 所以**不能按位映射**，必须拆串。

### 2.2 三步拆串（正则，确定性，不用模型）

| 步 | 动作 | 正则 | 对第 1 条的实测结果 |
|:--|:--|:--|:--|
| ① 剥方括号段 | 取 `【…】` 作为**公共描述**（不是维度） | `【([^】]*)】` | `bracket='实木-可移动-翻盖可调节'`，剩余 `527胡桃色（长40）` |
| ② 剥尾部圆括号 | 取括号内为**尺寸**（全角/半角括号都吃） | `[（(]([^（）()]*)[)）]\s*$` | `size='长40'`，剩余 `527胡桃色` |
| ③ 剥前导数字码 | 取 2–6 位前导数字为**货号** | `^\s*(\d{2,6})(?=[^\d]|$)` | `code='527'`，剩余 `rest='胡桃色'` |

拆完 6 条的真实结果（`parse_sku_name()` 实跑输出）：

| # | `code` | `bracket` | `size` | `rest` | 判定 |
|:--|:--|:--|:--|:--|:--|
| 0 | `''` | `2026款实木藤编茶边几` | **`''`** | `新品限时特卖` | **缺维度 → 跳过** |
| 1 | `527` | `实木-可移动-翻盖可调节` | `长40` | `胡桃色` | ✅ |
| 2 | `527` | 同上 | `长40` | `白色` | ✅ |
| 3 | `528` | 同上 | `长60` | `胡桃色` | ✅ |
| 4 | `528` | 同上 | `长60` | `白色` | ✅ |
| 5 | `528` | 同上 | `长60` | `黑色` | ✅ |

**交叉验证（拆得对不对的一条硬证据）**：`code` 与 `size` 是**一一对应**的 —— `527 ⇔ 长40`（3 条）、`528 ⇔ 长60`（3 条），零例外。
说明货号和尺寸是同一个变量值，拆出来的 `size` 不是噪声。

### 2.3 从「位置」升成「维度」（决定哪一维是 `规格1`）

```
候选位置：rest（颜色） 和 size（尺寸）
规则：某个位置在全商品内只有 1 个取值 → 不是维度，折进公共描述（不写进规格槽）
      —— 例：bracket 六条全同，长度恒定为 '实木-可移动-翻盖可调节'，所以它不是维度
排序：颜色类维度 → 规格1；尺寸类维度 → 规格2
      （依据：SKU 预览图通常跟颜色走，颜色做主规格更合用；且这是业界惯例 —— 平台是否强制，
       见 04-⑤）
```

实跑输出（`build_dimensions()`）：

```json
[{"name": "颜色分类", "values": ["胡桃色", "白色", "黑色"], "src": "rest"},
 {"name": "尺寸",     "values": ["长40", "长60"],             "src": "size"}]
```

→ 与任务书给的「颜色分类=[胡桃色,白色,黑色] × 尺寸=[长40,长60]」**完全一致**。
维度名的判定是关键词启发式（颜色词表 / 尺寸词表），**名字只用于我们自己的报告，不进 Excel**
（模板没有规格名列）—— 所以这个名字对吗其实不影响导入结果。

### 2.4 那个「促销款」SKU 怎么处理（这里踩过一次坑，写下来）

`新品限时特卖【2026款实木藤编茶边几】` 拆出来 `rest='新品限时特卖'`、`size=''`。

**第一版算法把它算进了颜色维度 → `颜色分类` 变成 4 个值（`胡桃色/白色/黑色/新品限时特卖`），缺失组合从 1 个炸成 3 个。**
这是错的：`新品限时特卖` 是营销词，不是颜色。

改法是两条（都已落进脚本）：

1. **学维度时只用「rest 与 size 都非空」的那批**（本例 5 条），促销款不参与学维度；
2. **写行时，任何一个维度取不到值就跳过该 SKU**（并记进 `report.unparsed`），绝不用空串凑。

实测修正前后：

| | 维度 | 缺失组合 | 写出行数 |
|:--|:--|:--|:--|
| 修正前 | 颜色分类(4) × 尺寸(2) | **3** 个（含 2 个假组合 `新品限时特卖/长40`、`新品限时特卖/长60`） | 6 |
| 修正后 | **颜色分类(3) × 尺寸(2)** | **1** 个（`黑色/长40`） | **5** |

### 2.5 缺失组合怎么处理（`黑色 × 长40`）

3×2 = 6 个理论组合，实际只有 5 个，缺 `黑色/长40`。

| 策略 | 行为 | 适用 |
|:--|:--|:--|
| **`skip`（默认）** | 只写实际存在的 5 行，缺的组合**不生成**，记进 `report.missing_combos` | 推荐。理由：模板要求一行一个**真实 SKU**；凭空造行等于凭空造一个「拍下无货」的 SKU，且它的价格/图/编码都没有来源 |
| `zero` | 生成缺失组合的行，价格留空、库存 0 | 仅当确认「平台要求笛卡尔积补全」时才用。**风险：库存 0 的行会不会被平台拒收，未知**（04-⑦） |

**为什么默认 skip**：样本里两个商品都是 4 行整整齐齐，**没有缺组合的样例**，所以「平台是否要求补全」没有证据；在没有证据时选「不制造虚假数据」那一侧。

## 3. `to_excel.py` 用法

```powershell
# 单文件
python to_excel.py ..\crawl3\plan-1436.json --out out\dy-excel-1436.xlsx --report out\report-1436.json

# 批量（一个 xlsx 装多个商品）
python to_excel.py "..\crawl3\plan-*.json" --outdir out

# 图片已经有公网地址时（映射文件 {本地绝对路径: URL}）
python to_excel.py plan-1436.json --img-mode map --img-map img_url_map.json

# 需要笛卡尔积补全 / 促销款也要单独成行
python to_excel.py plan-1436.json --fill-missing zero --unparsed as-is
```

### 3.1 参数表

| 参数 | 默认 | 作用 |
|:--|:--|:--|
| `plans`（位置参数） | —— | `plan-*.json`，支持通配符 |
| `--out` / `--outdir` | `out/` | 单文件输出路径 / 批量输出目录 |
| `--sheet` | `示例2模板` | sheet 名，照抄模板 |
| `--img-mode` | `placeholder` | `placeholder`=用 `--img-base` 拼占位 URL（**只验证结构，不能真导入**）/ `empty`=留空 / `map`=查映射表 |
| `--img-base` | `https://example.invalid/dy` | placeholder 模式的 URL 前缀 |
| `--img-map` | 无 | JSON：`{本地绝对路径: 公网URL}` |
| `--fill-missing` | `skip` | 缺失组合：`skip` / `zero` |
| `--unparsed` | `skip` | 拆不出规格的 SKU：`skip` / `as-is`（原串当规格名写一行） |
| `--price-format` | `raw` | `raw`(419.0→`419`) / `int` / `dec2`(→`419.00`) |
| `--attr` | 无 | 追加/覆盖属性，`--attr 风格:简约` |
| `--report` | 无 | 把拆解统计写成 JSON |

### 3.2 脚本里的关键实现点（改了别踩回去）

| 位置 | 做法 | 为什么 |
|:--|:--|:--|
| `COLUMNS` 常量 | 16 个列名**逐字照抄**模板第 2 行 | 列名错一个字就可能整批失败；已知表头一致性有断言（第 6.2 节） |
| 第 1 行 | `A1` 写说明 + `merge A1:N1` + 红字 + 自动换行 | 与模板 `A1` 的形态一致（模板里它就是红色说明） |
| 第 2 行 | 表头加粗 | 与模板一致 |
| 第 3 行起 | 数据；**商品首行写 16 列，后续行只写 A 与 G–N** | 模板 `B4..F6/O4..O6/P4..P6` 全空 |
| `PRODUCT_LEVEL` 集合 | 商品级列集中定义 | 改布局只改一处 |
| 空值 | 写 `''`（不是 `None`） | 模板 `J3/K3` 读出来是 `''` 而非 `None`，跟着走 |
| 详情图 | `','.join()` | 模板 `O3` 是 U+002C 分隔 |
| 属性 | `键:值` + `；` | 模板 `P3` 是 U+003A + U+FF1B |
| 图片 | 全部走 `ImgResolver` | 上传是外部动作，脚本只管「有 URL 就填、没有就报数」 |
| `商品ID` | 统一 `str(pid)` | 模板自己有 int/str 混用，统一成字符串更安全 |

## 5. 还没解决、也不该由脚本解决的

1. **图片必须先变成公网 URL** —— 脚本只提供三种模式，不做上传。没有这一步，产出的 xlsx **不能真导入**。
2. **抖动平台的强校验规则**（哪些列必填、库存 0 能不能过、价格能否带小数、属性键要不要用标准值）—— 模板样本里没有一条明文，只能靠一次真实导入试出来。
3. **官方模板的完整列集** —— 手上这份是 openpyxl 生成+WPS 手改的「示例2」，不是官方导出，所以「16 列够不够」这件事没被证明。
