## 0. 先说一件会影响全部结论的事：这不是平台官方导出的模板

`docProps/app.xml` 与 `docProps/core.xml` 的原文：

```xml
<Application>Microsoft Excel Compatible / Openpyxl 3.1.5</Application>
<dc:creator>openpyxl</dc:creator>
<cp:lastModifiedBy>代打哥</cp:lastModifiedBy>
<dcterms:created>2024-08-30T05:53:00Z</dcterms:created>
<dcterms:modified>2026-05-07T08:54:39Z</dcterms:modified>
<property name="KSOProductBuildVer">2052-12.1.0.25865</property>   <!-- WPS -->
<workbook ... xmlns:dbsheet="http://web.wps.cn/et/2021/dbsheet">  <!-- WPS 智能表格扩展 -->
```

三条硬结论：

1. **这个文件是 openpyxl 脚本生成的**（`creator=openpyxl`、`Application=Microsoft Excel Compatible / Openpyxl 3.1.5`），创建于 2024-08-30；**最后一次保存是人用 WPS 改的**（`lastModifiedBy=代打哥`、`KSOProductBuildVer`、`dbsheet` 命名空间）。
2. 表名 `示例2模板` 里的「示例2」说明**它自己承认只是一个示例**，配套的「示例1」等 sheet 不在这个文件里（`xl/workbook.xml` 只有 1 个 `<sheet>`）。
3. `A1` 原文明说：「当前模板为示例参考，**导入数据包可兼容其他软件导出字段信息**，详见教程帮助文档」。
   → 这句话的含义是「这个格式能被导入通道吃下」，**不等于「这是平台的完整字段清单」**。

**所以：本文档描述的列集只能证明「这 16 列这样写可以导入」，不能证明「只要这 16 列就够」。**
缺字段判定见 `04-待确认.md` 第 1–3 条。

## 3. SKU 行的组织规律（本节最要紧）

### 3.1 一句话结论

**一个 SKU 一行；一个商品 = 连续 N 行，第 1 行额外带上商品级字段，后续行这些列留空。**

### 3.2 逐行角色（样本 8 行全部标出）

| 行 | 角色 | 该行填了什么（列） |
|:--|:--|:--|
| 3 | **商品 31054 的首行 = 商品级 + 第 1 个 SKU** | A B C D E F G H I J K L M N O P（**全 16 列**） |
| 4 | 商品 31054 的第 2 个 SKU | A G H I J K L M N（9 列） |
| 5 | 商品 31054 的第 3 个 SKU | A G H I J K L M N |
| 6 | 商品 31054 的第 4 个 SKU | A G H I J K L M N |
| 7 | **商品 31055 的首行 = 商品级 + 第 1 个 SKU** | A B C D E F G H I J K L M N O P |
| 8 | 商品 31055 的第 2 个 SKU | A G H I J K L M N |
| 9 | 商品 31055 的第 3 个 SKU | A G H I J K L M N |
| 10 | 商品 31055 的第 4 个 SKU | A G H I J K L M N |

证据：`B4..B6`、`C4..C6`、`D4..F6`、`O4..O6`、`P4..P6` 全部为 `None`（未写入），而 `A4..A6` = `'31054'`、`G4..N6` 有值。

### 3.3 商品级 vs SKU 级 的列划分（实测）

- **商品级（只写首行）**：`商品标题 / 商品分类 / 商品轮播图1-3 / 商品详情图 / 商品属性`
- **SKU 级（每行都写）**：`商品ID / SKU规格名称 / 规格1 / 规格2 / 规格3 / SKU编码 / SKU库存 / SKU拼单价 / SKU预览图`
- **`商品ID` 的特殊性**：它虽然是商品级概念，但**每行都重复填**（`A3=31054, A4..A6='31054'`）——它是把多行**粘成同一个商品**的锚点。

⚠️ **样本自己有个坑**：`A3` 是 **int 31054**，`A4..A6` 是 **字符串 '31054'**（`A7` 同理）。同一个商品里 ID 的类型都不统一，说明平台是按**值的文本形态**做分组，不按单元格类型。我们生成时统一写字符串即可（`to_excel.py` 已统一成 `str(pid)`）。

### 3.4 多规格怎么写：有「规格1/规格2/规格3」三列，但**没有规格名**

关键事实（这条决定整个转换方案能否成立）：

- 列名里只有 `规格1` `规格2` `规格3` **三个位置槽**，**没有任何一列装「规格名称」**（没有「颜色分类」「尺码」这类维度的名字）。
- 唯一的「名称」列是 `SKU规格名称`（G），而它的值是**各维度的取值拼起来**：

```
G3 = 'HP31054 M'   =  H3 'HP31054' + ' ' + I3 'M'
G4 = 'HP31054 L'   =  H4 'HP31054' + ' ' + I4 'L'
G5 = 'HP31054 XL'  =  H5 'HP31054' + ' ' + I5 'XL'
G6 = 'HP31054 XXL' =  H6 'HP31054' + ' ' + I6 'XXL'
```

**取值规则（实测，4/4 行成立）**：`SKU规格名称 = 规格1 + " " + 规格2 (+ " " + 规格3，非空时)`，分隔符是**半角空格**；空槽（`J` 的 `''`）不参与拼接。

**维度顺序规则**：`规格1` 是第一维、`规格2` 是第二维、`规格3` 是第三维，**位置即层级**，靠列顺序传递，不靠名字。
本样本只有 2 维（`规格1` 恒定 = 货号 `HP31054`，`规格2` = 尺码），所以**「一个商品能不能有 1 维 / 4 维」这里没有证据** → 04-⑤。

> ⚠️ 本样本的 `规格1` 在 4 行里**完全相同**（`HP31054`），也就是说「第一维只有 1 个取值」是合法的、被样本用过的形态。
> 这对我们的数据有直接含义：我们那 6 条 SKU 里「颜色/尺寸」拆出来后，**不能把恒定值（如「实木-可移动-翻盖可调节」）也当成一维**，否则会凭空多出一个只有 1 个取值的维度（`to_excel.py` 已按「取值 <2 个就折叠」处理，并保留了一条 `规格1` 恒定值也能写出的能力）。

## 4. 图片列：位置 / 多图分隔 / 到底是路径还是 URL

| 图片用途 | 列 | 一格装几张 | 分隔符 | 样本里的形态 |
|:--|:--|:--|:--|:--|
| 商品轮播图 | **D / E / F**（3 个独立列） | **每列 1 张** | 不适用 | `https://1832850322.v.123pan.cn/.../xxx.jpg` |
| SKU 预览图 | **N**（1 列） | **每列 1 张** | 不适用 | 同上 |
| 商品详情图 | **O**（1 列） | **一格多张** | **ASCII 逗号 `,`（U+002C）** | `O3` 实测 16 个 URL，`O7` 实测 16 个 |

逐字符验证（我按码位查的，不是看外观）：

- `O3` 里的分隔符是 `U+002C`（半角逗号），**不是** `，`（U+FF0C 全角）、**不是** `|`、**不是** 换行。
- `O3` 共 16 个 URL、15 个 `U+002C`；`O7` 同样 16 个 URL。
- URL 里的冒号是 `U+003A`（半角），无空格残留。

**图片列要求的是 URL，不是本地路径 —— 证据是样本本身**：`D3`、`N3`、`O3` 全是 `https://1832850322.v.123pan.cn/...`（123 网盘直链）。样本里**没有任何一个本地盘符路径**，也没有 `file://`。
→ 「能不能填本地路径」未验证；从「批量导入要在服务端抓图」这个常识推断必须能被公网抓到，见 04-③。

**数量上限**：轮播图恰好 3 列 → **3 张是模板给定的上限，不是巧合**（多出来的没有列可放）。详情图上限未知（样本 16 张能过，说明 ≥16）。SKU 预览图 1 张。

## 5. 属性列（P）的格式要求

- 实测原文（`P3` / `P7` 一致）：`材质:棉；品牌:范小懒`
- 逐码位：`材质` `:`(**U+003A 半角冒号**) `棉` `；`(**U+FF1B 全角分号**) `品牌` `:`(U+003A) `范小懒`
- 即：**`键:值` 对，键值之间用半角冒号，条目之间用全角分号 `；`**，结尾不留下多余分隔符。
- 是否需要对照平台标准值：**本样本无法判断**。`材质:棉`、`品牌:范小懒` 看起来是自由文本（`范小懒` 是店铺/品牌自拟名，不是平台品牌库里的标准值）。→ 04-④。
- 明文：`A1` 第 3 条「商品属性字段非强校验，若无也可导入」→ **P 可以整列空着导入**。

## 9. 一句话总结

**单 sheet、16 列（A–P）、表头在第 2 行、第 1 行是合并的红色说明；
一个 SKU 一行，商品首行带商品级字段（标题/分类/轮播图1-3/详情图/属性）、后续 SKU 行只填 A 与 G–N；
规格靠 `规格1/规格2/规格3` 三个位置槽表达（位置即层级，**没有规格名列**），`SKU规格名称` = 各槽取值用半角空格拼起来；
轮播图 3 个独立列各 1 张、详情图 1 格 ASCII 逗号拼多张、图片全是 https URL、属性 `键:值` 用半角冒号 + `；` 分隔。**
