## 零、三条上货链路（这是全篇结论）

| 链路 | 入口 | 适用 | 稳定性 | 自动化难度 |
|:--|:--|:--|:--|:--|
| **A 标准表单** | `/ffa/g/create?cid=<类目ID>&entrance=create` | 单个、要精确控制每个字段 | ★★★ 字段级可控 | 中（76 个输入框，但有明确标签） |
| **B AI 创建** | `/ffa/g/create`（无 cid） | 手上有图 + Excel，让平台自己识别填 | ★★ 受 AI 结果影响 | 低（上传文件 → 下一步 → 核对） |
| **C Excel 批量** | 商品管理 → 更多操作 → **Excel导入** | 批量**修改**已有商品 | ★★★ 平台自己的批处理 | 最低（下载模板 → 填 → 上传） |

**实测纠正一条关键认知**：`更多操作 → Excel导入` 打开的是「批量优化/批量修改」弹窗
（一、选择修改内容 → 二、下载修改模板 → 三、导入模板），它**改的是已有商品，不是新建**。
所以「批量新建」目前只有 A / B 两条路；C 只能用来批量改价、改标题、改库存。

**推荐组合**（对上货台最省事）：
```
每个商品：A 表单跑一次（首次铺货，字段全控）
日常批量：C Excel 批量改（改价、改库存、改标题）
新品试水：B AI 创建（图 + Excel 丢进去，人工核对 AI 结果再提交）
```

## 六、抗改版写法（这是唯一的技术难点）

抖店 class 名是编译产物（`auxo-*` 前缀 + 随机串），**禁止写死**。实测可用的四类定位：

| 方式 | 示例 | 稳定性 |
|:--|:--|:--|
| 可见文本精确 | `text="发布商品"`、`text="更多操作"`、`text="Excel导入"` | ★★★ |
| 文本 + 序号 | `text="编辑" >> nth=0`（列表每行都有「编辑」，必须给序号） | ★★★ |
| 占位符 | `input[placeholder*="请输入商品名称"]` | ★★ |
| 结构关系 | 「找 label 文本 → 取它的父块 → 在块内找 input」 | ★★ |

**实测踩过的坑（写脚本时必守）**：
1. **列表页每个商品行都有「编辑」，直接 `text="编辑"` 会报 `matched 2 elements`** → 必须 `>> nth=N`。
2. **点「编辑」会开新标签页**（p2），不是当前页跳转 → 脚本要 `task.adopt()` 或直接拼 URL。
3. **编辑页 URL 可直接拼**：`/ffa/g/create?product_id=X&cid=Y&entrance=edit` —— 比点击稳定得多，
   这是**首选**定位方式（URL 比 DOM 稳）。
4. **`page.evaluate` 只读主文档**；抖店是 Garfish 微前端，个别子应用在 iframe 里（本次表单在主文档，已验）。
5. 菜单要**先点「展开导航」**才渲染全部 60 项。

必须由脚本按店铺默认值补齐（建议：一次性取一个已发布商品的这些值，作为「店铺默认模板」复用）。
