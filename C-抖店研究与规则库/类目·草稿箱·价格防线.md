## 一、类目：新版根本不给手选

### 1.1 事实链

| 事实 | 证据 |
|:--|:--|
| 新版 `/ffa/g/create?cid=1000004588` **仍然只给 AI 创建页**（上传主图/详情/Excel/截图 → 下一步生成），没有类目选择器 | `[实测]` 截图 `crawl2/probe-create-cid.png`，body 仅 268 字 |
| 点「返回旧版」才有传统表单，但首屏只要求 **`*商品主图` + `*商品标题`** | `[实测]` `crawl2/old-create.json`：labels=`*商品主图 / 商品正面图 / *上传主图 / *商品标题` |
| **新版不支持手选类目** —— 接口字段 `select_category_limit: "not_support_manual_select"` | `[实测]` `predictCategoryN` 响应 |
| 类目由模型预测，最多给 5 个候选；预测不准可申诉（`support_category_appeal: true`） | `[实测]` 同上，`category_sort_source: "model_top_5"` |
| 编辑已有商品时，类目只能点「修改」→ 弹「修改类目可能会导致部分内容丢失，确认修改？」→ 再点「修改类目」 | `[实测]` `crawl2/cat-modal-live.json` |

**结论：你记的"上传主图+标题系统自动分类目"是对的，而且新版把这件事变成了唯一路径 —— 手选通道被关掉了。**

### 1.2 类目预测接口（`predictCategoryN`）

```
POST /product/tproduct/predictCategoryN?appid=1
→ data.candidate_category_details[]  每个候选带三级 cid
→ data.select_category_limit         not_support_manual_select
→ data.support_category_appeal       true（可申诉）
```

**真实响应（本店现有商品的预测结果，`[实测]`）**

| 顺序 | 完整路径 | leaf_cid | status | 能否建 |
|:--|:--|--:|--:|:--|
| 1 | 家具 > 床 > 床架/床板 | `1000009324` | 0 | ✅ |
| 2 | 家具 > 硬木家具 > 床类 | `1000009367` | 0 | ✅ |
| 3 | 家具 > 床 > 皮艺床 | `1000004546` | **2** | ❌ 需先开通资质 |
| 4 | 家具 > 沙发 > 皮艺沙发 | `1000004512` | 0 | ✅ |
| 5 | 家具 > 床 > 板木结合床 | `1000009328` | 0 | ✅ |

- `status=0` → 可直接建品
- `status=2` → **未开通类目**，`disable_desc` 里给开通链接：
  `/ffa/grs/qualification/list?source=product&type=3&cids=1000004546`
- `is_fill_category_tree=false` 同样表示不可建

### 1.4 类目树怎么拿（三条路，按性价比排序）

1. **让模型给**（推荐）：传标题/主图 → `predictCategoryN` → 5 个候选 cid。**不需要预先知道全树**，这正是新版设计意图。
2. **列表页筛选器逐级点**：`/ffa/g/list` 顶部「类目名称 · 请选择类目」→ 一级 32 项已抓到（`[实测]` `crawl2/cat-tree.json`）：
   `玩具/乐器及配件 · 服装 · 个人护理 · 家清纸品 · 五金/工具 · 电子/电工 · 家具 · 家装灯饰光源 · 家装建材 · 居家日用 · 汽车用品/整车及配件 · 摩托车 · 电动车 · 自行车用品 · 餐饮厨具 · 农资园艺 · 本地生活服务 · 元器件 · 办公设备及耗材 · 电器 · 3C数码及配件 · 文教文化用品 · 鞋靴 · 箱包 · 运动休闲用品 · 户外装备 · 钟表眼镜 · 民俗工艺/非遗`
   —— 你要的 **家具 / 户外装备 / 家装灯饰光源** 都在这 32 项里。
3. **从已有商品反推**：`tproduct/list` 每件都带 `category_leaf_id / first_cid / second_cid / third_cid / category_name`，全店 3846 件就是一手的类目样本。

### 1.5 还没打通的（如实写）

- `getSchema` 的请求字段名未定：传 `{category_id: xxx}` 返回「类目ID必传」，说明字段名不是这个（可能是 `cid`）。**表单定义（131KB）已抓到完整响应**，只差请求参数名。
- `predictCategoryN` 传 `{title}` 返回 `st:10004 参数错误` —— 至少还需要图片或别的必填字段。

## 二、草稿箱：一条 GET 就够，不用点 UI

### 2.1 接口

```
GET /product/tproduct/list?appid=1&page=0&pageSize=50&draft_status=0&tab=all
```

返回 77 KB/页，字段极全（约 180 个）。关键字段：

| 字段 | 说明 |
|:--|:--|
| `draft_status` | **1 = 草稿** |
| `status` | 0=下架 / 1=售卖中 |
| `check_status` | 审核状态 |
| `reason` / `audit_reason` | 驳回原因 |
| `category_leaf_id` / `first_cid` / `second_cid` / `third_cid` | 类目 |
| `category_name` / `shop_category_path` | 类目名 |
| `pred_category_detail` / `recommend_category` / `category_misplace_info` | 类目预测与错放信息 |
| `market_price` / `discount_price` / `price_lower` / `price_higher` | **单位＝分** |
| `skus[]` | SKU 明细（列表接口返回为空，需单独拉） |
| `draft_time` / `draft_time_tips` | 草稿时间 |
| `product_id` / `img` / `stock_num` / `sell_num` | 基础 |

### 2.2 实测门店现状（`[实测]` 2026-10-29 14:42）

```
总商品   3846 件
├ 草稿        2633 件   ← 全是已建未发
├ 售卖中        44 件
└ 下架         323 件
（本次读取截断在 3000 件，MAX_PAGES=60 × 50）
```

**你之前说"205 件未上架、数字自己在涨"—— 现在是 2633 件草稿。** 这个数字要复核是谁在建。

### 2.3 草稿箱在 UI 里的位置

`/ffa/g/list` 的 tab 栏含 **`草稿箱`**（`selectors.json.goods_list.tabs`）。URL 参数实测出现 `?sov_draft_status=0&sov_goodsType=0`。

**推荐做法：读草稿走接口（快、全、带全部字段），写/审核走 UI（可留痕）。**

## 三、价格防线：计算器已跑通，157 件必须改

### 3.1 规则依据（全部官方原文，`rules/md/`）

| 规则 | 官方原话 | 对应检查 |
|:--|:--|:--|
| **R1 虚构被比较价格** | "某个水杯商品售价50，商家在商品信息上无依据虚构原价1000" | 划线价 / 售价 倍率 |
| **R2 价格设定不合理** | "商品销售价格不在所发布类目的常规价格区间内或设置价格显然异常"／"标价99999元起的气垫" | 绝对高价 / 低于 1 元引流 |
| **R3 同商品 SKU 价差** | "同商品下各SKU之间的销售价格价差存在显然不合理性" | SKU max/min |
| **R4 赠品价高于主商品** | "商品售价288元，赠品标价1761元" | 赠品价 / 主商品价 |
| **R5 标题宣传价格** | "禁止在标题中宣传价格" | 标题含 ¥/元/裸价 |
| **R6 违规价格营销词** | "跳楼价、清仓价、亏本价、甩卖价、白菜价、恐怖价、自杀价、倒闭价、破产价、处理价" | 词表匹配 |
| **R7 限时优惠未注明时间** | "限时促销应当准确标注开始、结束时间" | 限时词 + 无日期 |

### 3.2 实测结果（3000 件，`[实测]`）

```
必须改 157 件 │ 需复核 471 件 │ 通过 2372 件
规则命中：R1 = 597 次，R2 = 74 次
最高划线倍率：12.8 倍（沙发垫 售价 476 / 划线 6092.8）
```

**采样（前 8 件必须改）**

| 商品 | 售价 | 划线价 | 倍率 |
|:--|--:|--:|--:|
| 实木沙发垫 | 476 | 6092.8 | **12.8×** |
| 实木双人床 | 318.92 | 3065.44 | 9.6× |
| 儿童收纳架 | 399.84 | 2551.36 | 6.4× |
| 铁艺床 | 364 | 2244 | 6.2× |
| 军绿色货架 | 492 | 2981 | 6.1× |
| 内衣店货架 | 488 | 2692 | 5.5× |
| 电脑桌 | 416 | 2222 | 5.3× |
| 服装店中岛桌 | 482 | 2450 | 5.1× |

**这直接对上你店被罚的两条「优惠价格虚假」。** 157 件若不改直接发布，等于主动送出 157 条违规。

## 五、接口契约速查

```
GET  /product/tproduct/list?page=&pageSize=&draft_status=&tab=all     商品/草稿列表（77KB/页）
POST /product/tproduct/getSchema?appid=1                              按 cid 出表单定义（131KB，字段名待定）
POST /product/tproduct/refetchSchema?action=<动作>&quality_key=<k>    资质选项/白底图/运费模板等子取数
POST /product/tproduct/asyncRefetchSchema?action=category_prefill_check
POST /product/tproduct/predictCategoryN?appid=1                       类目预测（返回 5 候选）
GET  /product/tproduct/listProductTemplate?template_type=&category_id= 模板（category_property / sell_info）
GET  /product/category/*                                              ❌ 全部 404（路径不是这个）
```

`refetchSchema` 的 `action` 取值（实测出现）：
`qualification_options_load` · `white_background_refresh` · `freight_template_options_load` · `pic_fmt_convert` · `pic34_fmt_convert` · `freight_reasonableness_refresh`

请求体统一是 `{trigger:[], trigger_type:"", context:{category_id, biz_identity:"xiaodian", business_code:"xiaodian", gray_components:[...], feature:{...}}}`。
