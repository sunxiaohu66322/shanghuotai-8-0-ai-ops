## 结论摘要（先说三句最要紧的）

1. **「商品详情视频」和「内容视频挂商品」是两条完全不同的链路，不能混为一谈。** 前者是商品详情页里的一个视频字段；后者是往抖音/视频号发一条作品、并在作品上挂商品链接。两者账号、接口、权限、人工量全不一样。
2. **主人题目里「发布后关联商品」这个说法，微信官方明文不成立**：《商品分享视频创作指引》原文「**目前只能在发表时添加商品，无法对已经发表的内容添加商品**」`[官方文档]`。抖音同样是发布页「添加商品」那一步完成。**所以"关联"必须和"发布"绑在同一次操作里，不能事后补。**
3. **"最少账号、最少人工"能做到的上限**：微信侧商品头视频可做到近全自动（现有 2 个店 appid 已通、有官方 API、E1 副本已铺路）；**内容视频的发布 + 挂商品，两个平台都必须人工在发布那一步点**（无 API、且需先开通带货权益）。自动化只能帮到"素材备好、表单填好、跳到发布页"，最后一下必须人点。

> **本抖音章必须区分的三件事**（主人点名）：
> - **商品详情视频上传** = 抖店商品「主图视频」，是商品素材，走抖店后台（本机 xlsx 未带、API 未建应用 → 现阶段只能浏览器补）。
> - **抖音短视频发布** = 抖音开放平台 `video.create`，另起账号体系。
> - **短视频商品锚点关联** = 发布页「添加商品」，无 API、需带货资格、且**只能在发布时做**。
> 三者不是一件事，开通任何一个不等于开通其他。

### ★ E1 `head_videos` 方案的边界（主人点名，必须写清）

> **E1 只解决「商品头图视频」—— 即商品详情页里、轮播图位置那个视频。它完全不涉及视频号作品发布，也不涉及作品挂商品。**

- E1 交付的是 `_e1dev\wxapi_e1.py`：本地 mp4 → 微信 4 步上传（initupload/uploadpart/finishupload/getplayinfo）→ 临时 `video_url` → 填进 `product/add|update` 的 `head_videos`。**终点是"商品对象多了个视频字段"，不是"视频号里多了一条作品"**。`[源码确认]` E1 报告 §1/§6
- E1 只到「副本逻辑正确 + Dry-run 12/12」层，**未对真实后台 / 真实商品提交过**；字段名、4 接口真实参数、临时地址时效仍待 E2 核实。`[本机实测]` E1 报告 §8
- 别把"小店素材上传"当成"视频号发布"（7.0 矩阵 §4.1 明列此误判）。**用 E1 去回答"内容视频怎么发、怎么挂车"是答非所问。**

## 四、最终必答（9 条）

**1. 是否需要额外注册抖音账号？**
- 只做**商品详情视频**：不需要新账号，用现有抖店后台补主图视频即可（浏览器）。
- 要做**内容视频发布 + 挂车**：需要**一个抖音号**（这跟"抖店"不是同一个东西）。若抖店后台已绑过官方抖音号 → 复用那个，先去后台核实；若没绑 → 需要一个抖音号并满足带货门槛（实名 / 1000 有效粉或店铺自营 / ≥10 条公开视频 / 保证金）。**本机无法核实是否已绑**，这是第一件要主人去后台看的事。
- 另需**抖音开放平台应用**（不是抖音号本身），`video.create` 权限默认关闭、要申请。

**2. 是否需要额外注册视频号？**
- 只做**商品头视频**：不需要，两店 appid 直接够用。
- 要做**内容视频 + 挂商品**：需要**一个视频号**。微信小店可用「店铺自营账号」关联视频号（后台发起 + 管理员扫码），关联后能带自己小店的商品。若两店都还没关联 → 新建或关联 1 个即可，**一个视频号只能关联一个小店**。本机 `shops.json` 无绑定记录，需主人到后台「店铺关联账号」核实。

**3. 现有账号能不能直接使用？**
- ✅ **能直接用**：微信两店的**商品头视频 API**（appid 已通，E1 已铺路，E2 核字段即可上）。
- ❌ **不能直接用**：抖店商品 API（未建应用）、抖音短视频发布（未建应用/未授权/无带货资格）、视频号发布挂车（无 API + 带货权益未核实）。这些是**账号与权限问题，不是写代码能绕过的**。

**4. 商品详情视频怎么上传？**
- 微信（推荐主线）：拼多多采集的 mp4 **先下载到本地** → E1 的 4 步上传链路换出 `mmecimage.cn/p/` 临时 `video_url` → 随 `product/update` 提交 `head_videos: {video_url}` → `product/get` 回读确认。第三方直链不能直填（`10020035`）。临时链即时用、不入库。
- 抖音：抖店后台商品编辑页补「主图视频」（浏览器），或待建抖店应用后走官方「应用主图视频至商品」。本机 16 列 xlsx 需补一列视频路径才能带进上架流程。

**5. 内容视频怎么发布？**
- 微信视频号：**视频号助手网页/客户端人工发**（官方无 API）。可自动化到"备好视频+文案+封面、停在发布页"。
- 抖音：人工在创作者平台/App 发；或取得 `video.create` 权限后 API 发（发布后先进审核、期间仅自己可见）。

**6. 发布后怎么关联自己的商品？**
- **纠正前提：不存在"发布后关联"。** 微信官方明文「只能在发表时添加商品，无法对已发表内容添加商品」；抖音也是发布页「添加商品」那一步。
- 正确做法：**发布那一次操作里同时完成关联** —— 先把商品加入橱窗（微信可用 `windowproduct` API 铺货 / 抖音后台选品），发表时从橱窗选对应商品或贴商品链接。且内容需与商品相关。
- 因此"关联"这一步天然带人工，自动化只能做到"提前把商品铺进橱窗 + 生成好待发布表单"。

**7. 哪些环节可以自动化？**
- 本地：拼多多视频下载、格式/时长检查、转码裁切、去第三方水印外处理、按商品 ID 归档（纯本地 ffmpeg，零平台依赖）。
- 微信商品头视频：**整条可 API 自动化**（4 步上传 + `head_videos` 写入 + 回读核对），E2 后即可上。
- 微信橱窗铺货：`windowproduct/api_addwindowproduct` 可 API。
- 抖音短视频发布：取得 `video.create` 权限后发布动作可 API（挂车仍人工）。
- 表单预填 + 跳转发布页：浏览器自动化可做。

**8. 哪些环节必须人工操作？**
- 账号侧：抖店/抖音应用创建与资质审核、OAuth 扫码授权、带货权益/保证金、视频号与小店关联扫码 —— **全部首次必须人做，且不可自动化绕过**。
- 发布侧：视频号作品发布与"发表时挂商品"、抖音发布页挂车、最终发布确认按钮 —— **平台无 API / 规则灰区，必须人点**。
- 权益未核实前的所有"内容视频"动作，一律人工。

**9. 第一阶段最简单的实施顺序（最少账号、最少人工）**

| 步 | 做什么 | 账号 | 人工量 |
|:--|:--|:--|:--|
| ① | 后台核实两件事：两微信店是否已关联视频号、抖店是否已绑官方抖音号（**只读查看，不改动**） | 现有 | 主人看一眼 |
| ② | **主线先上微信商品头视频**：E1 副本迁到生产 `wxapi.py`（4 接口）→ 拿 1 个草稿品做 E2 真实字段核对与一次 `head_videos` 提交 → 回读确认。这一步**现有 2 店直接用、零新账号、可全自动** | 现有微信 2 店 | 几乎零 |
| ③ | 上货台把库里 `role='video'` 的 194 条接进建品 payload（下载→上传→`head_videos`），批量给已有商品补头视频 | 现有微信 2 店 | 低 |
| ④ | 抖音侧先补 16 列 xlsx 的视频列 + 抖店后台浏览器补主图视频（不建应用、不新账号） | 现有抖店 | 中 |
| ⑤ | 橱窗铺货（微信 API / 抖音后台），为"发表时挂商品"备好货 | 现有 | 低 |
| ⑥ | 内容视频挂车：先人工跑通 1 条（微信视频号 + 抖音各 1 条），验证权益与流程；**确认稳定前不批量、不无人值守** | 需 1 视频号 + 1 抖音号 | 高（必须人点） |

> **最小闭环 = 第 ② 步**：现有账号、有 API、E1 已铺路，做完就能让「拼多多视频自动变成微信小店商品头视频」。第 ⑥ 步是另一个量级的事（要新账号、要权益、要人工），**别和 ② 捆在一起排期**。

## 五、本轮红线与未核实项

**红线遵守**：只读代码/配置/官方文档；未改生产代码、未发布真实视频、未修改任何商品、`v3.db` 零读写、`shops.json` 仅读字段名未打印 secret、零真实平台接口调用。

**`[尚未核实]` 清单**（不得当结论用）：
1. 两微信店后台是否**已关联视频号**、及各自「短视频商品分享权益」是否已开通。
2. 抖店后台是否**已绑定官方抖音号**、该号带货资格（粉丝/视频数/保证金）状态。
3. 抖店**商品主图视频**的上传 URL、字段名、应用流程官方原文（本轮只取到"存在该能力"）。
4. 抖音 `video.create` 之外是否另有**商品锚点**官方通道（官方锚点列表无商品，但未穷尽电商侧能力）。
5. E1 的 `video_url` 字段名、4 接口真实参数、临时地址时效 —— 归 E2，不属本轮。

**报告结论等级：B（条件部分满足）** —— 商品详情视频路径已明确且微信侧可落地；内容视频挂商品受平台规则限制，必须保留人工环节，无法做到"全自动化关联"。
