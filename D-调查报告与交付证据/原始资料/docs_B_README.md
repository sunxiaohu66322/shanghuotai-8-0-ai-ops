# 淘宝选品系统（v2 · 智能分析版）

**目标**：在淘宝上精选商品 —— 找出「同一件货被搬运的源头那家（价格最低）」，而不是一次扫 5 万条链接。
采集到的数据直接导出成微信小店的 `importCreate.csv`，拿去后台一键导入上货。

> **v2 的重心变了**：不是"采得多"，是"**看得出哪件值得做**"。
> 新增 **智能分析** —— 你在搜索页点一下，它当场告诉你哪些是源头、哪些是重点，**标签直接画在商品卡片上**。
> （另有一条并行线「19 列完整度」，见第六节。）

> **v2.1 新增「⚙ 筛选规则」面板**：所有筛选条件（阈值 / 权重 / 闸门 / 营销词表）都在界面上直接改、
> **即时生效**，不用改代码、不用重启服务。规则落在 `data/rules.json`，每次保存自动留备份。

## 零、筛选规则面板（v2.1）—— 改条件不用找人改代码

界面上点 **「⚙ 筛选规则」**，弹出的面板分四块：

| 块 | 管什么 | 典型改法 |
|:--|:--|:--|
| ① 认款 | 多大的差别还算「同一件货」 | 觉得同款太少 → 调低「共享核心词」门槛 |
| ② 打分 | 什么算「值得做」 | 更看重源头 → 调高「是源头」的分 |
| ③ 筛选闸门 | 哪些直接不要 | 只看 30~100 元 → 填价格上下限；不要某些店 → 填店铺排除词 |
| ④ 营销词表 | 哪些词算「堆词」 | 加自己的行业词 |

**保存即生效**：不重启、不重装插件。插件下次点「智能分析」就用新规则。
**恢复默认**：面板上「恢复默认」按钮，当前改动会挪成 `data/rules.json.bak-*` 备份。
**直接改文件也行**：编辑 `data/rules.json`，服务按文件修改时间自动重载；写坏了会自动回默认，不会崩。

## 二·五、同款判据是怎么定出来的（重要 —— 这里是踩过坑的地方）

**结论：判据是拿真实淘宝数据量出来的，不是拍的。** 量测脚本留在仓库里可复跑：

| 脚本 | 量什么 |
|:--|:--|
| `_量_真图判据.py` | 真实主图的 pHash / 颜色签名分布 |
| `_量_同款判据.py` | 各种标题相似度度量能不能分开真同款 |
| `_量_核心词数.py` | 共享「高 IDF 实义词」个数的分布 |
| `_量_双条件.py` | 绝对数 + 占比双条件在两个数据集上的表现 |
| `_验_端到端.py` | 在**真实淘宝页**上跑完整链路（识别→打分→画标签） |

### 被实测否掉的判据

样本：淘宝搜「落地灯」28 条真实商品，人工判定 4 组真同款。

| 判据 | 结果 | 铁证 |
|:--|:--|:--|
| 主图 URL / 图片 ID 直接比对 | ❌ | 真同款 0 组命中 |
| **pHash 感知哈希** | ❌ | 真同款 26~36，不同款 20~40，**完全重叠** |
| **颜色签名** | ❌ | 真同款 0.73~0.99，不同款 0.42~1.72，**完全重叠** |
| 标题 Jaccard / Overlap / IDF 加权版 | ❌ | 比例型度量**全部没有空隙** |

> 原因：淘宝搜索页的主图是**各卖家自己拍的场景图**，不是同一张货源图。
> 所以「图片指纹」这条路在搜索页上不成立 —— 这一点和 `_自检_分析.py` 的合成场景不同，
> 那个场景（同一张图被直传）是真实存在的，所以图片判据保留、两个场景各覆盖一半。

### 现在用的三条判据（并存，各覆盖一种场景）

1. **图片双签名**（`use_image`）—— 抓「同一张货源图被别家直传」
2. **共享高 IDF 核心词**（`core_word_min` / `core_ratio_min`）—— 抓「各卖家自己写的标题」
   真同款共享 12~15 个实义词（惠普/钢琴/护眼/全光谱），误报最多 12 个
3. **比例相似度**（`title_min_sim`）—— 抓「照抄标题」

**为什么三条都要**：IDF 在样本量小时不可靠（6 条标题时通用词全被滤掉），
所以核心词判据和比例判据必须并存。实测两边都验过（`_自检.py` 40/40 + `_自检_规则.py` 34/34）。

### 一个必须说清的限制

**同款判定会有误报，所以界面上给的是「置信度」不是铁结论**：
插件在卡片上标「同款·确定 / 同款·较可能 / 同款·存疑」，
低置信的「源头」在打分时**打折**（×0.6），不会给满分误导你。

---
**你手动决定采哪些** —— 不自动翻页、不自动打开页面。

## 三、智能分析怎么判的（v2 的重心）

分三层，逐层往下：**认款 → 定位源头 → 打分**。

### 3.1 认款 —— 这是同一件货吗

淘宝上一件货被几十家店搬来搬去，价格能差 4 倍。要认出「同一簇」，才有"源头"可言。

**图片用「双签名」，且两个都同意才算同图：**

| 签名 | 管什么 | 同图（含重传） | 异图 |
|:--|:--|:--|:--|
| **pHash**（裁白边后） | 有细节的图 | ≤ 18 | ≥ 24 |
| **颜色签名**（4×4 去均值） | 白底商品图 | ≤ 0.27 | ≥ 0.91 |
| **标题骨架**（bigram Jaccard） | 图取不到时兜底 | ≥ 0.62 | — |

- **两个签名都同意** → 算同图（这是防误聚的关键）
- 图不像但标题骨架像 → 也算同款
- **价格差 > 4 倍** → 直接不算同一件货

**为什么必须「裁白边 + 双签名」**（这段是实测踩出来的，**别改回去**）：

```
淘宝商品图大多是「纯白底 + 中间一个小主体」，这种图信息量极少。
· 不裁白边：同一张图缩放 80% 后 pHash 距离 32~36 → 认不出来
· 裁白边后：同一张图缩放/位移/转 JPG → pHash 0~18，颜色 ≤0.27
            不同商品               → pHash ≥24，颜色 ≥0.91
两段之间有明确空隙，阈值取在空隙中间。
```

> **踩坑记录**：这套签名第一版写错过两处，都会让"找源头"整个失效 ——
> ① 二维 DCT 写成了 `Cᵀ·arr·C`（该是 `C·arr·Cᵀ`），结果**灰度均值差 86 的两张完全不同的图指纹一模一样**；
> ② 不裁白边，导致同一张图重传后认不出。
> 两处都由 `_自检_分析.py` 的断言抓出来，现在都修了。

### 3.2 定位 —— 谁是源头

簇内**价格最低**的那家 = **源头**，卡片上打橙色「源头」标签，列表里也标。

### 3.3 打分 —— 值不值得做

| 维度 | 权重 | 说明 |
|:--|--:|:--|
| 搬运热度 | 每家 +4（上限 8 家） | 被很多人跟 = 爆款信号 |
| **是源头** | **+25** | 簇内最低价 |
| 偏便宜（前 1/3） | +12 | |
| 溢价空间 | 每多 1 倍 +10（上限 20） | 价差 = 你的毛利空间 |
| 销量信号 | +10 | 有"已售 N"就算 |
| 标题干净度 | 最多 +10 | 营销词少 = 更像源头而非二手商 |
| 已细采 | +5 | 有完整 SKU / 图 |

**≥ 55 分 = 重点**（插件画橙框 + 角标显示分数）。

**每一条都带「理由」** —— 不只给分，还告诉你为什么（鼠标停在分数上看）。

**想调口味**：改 `server/analyze.py` 顶部的 `W_*` 那组权重，不用动逻辑。

## 四、导出的 CSV 格式

严格对齐官方模板 `importCreate.csv`（**19 列，GBK 编码**）：

```
商品ID,商品名称,品牌,分类,库存,团购价格,单买价格,
商品主图,商品轮播图,商品详情图,商品描述,商品视频,商品属性,
SKUID,SKU名称,SKU库存,SKU团购价格,SKU单买价格,SKU预览图
```

多值分隔符（模板原本的写法）：
- SKU 系列 → `|` 分隔
- 图片系列 → `,` 分隔
- 商品属性 → `key:value|key:value`

导出时可传 `markup`（如 `0.3` = 整体上浮 30%）留定价空间。

## 六、19 列完整度（验收标准）

**验收标准就是这一条：`importCreate.csv` 里的 19 列，一列不落全采到。**

界面右上角「**19列完整度**」按钮点一下，直接告诉你：

- 每一列**采到了多少件**（如 `商品视频 12/30`）
- 哪些商品**还差几列**，差哪几列（鼠标悬停看清单）
- 全库有多少件是 **19/19 全齐**

**插件上也有**：详情页右下角那块面板，实时显示 `字段完整度 17/19`，下面 19 个小格逐列打勾/点灯 —— 哪个没采到一眼看见。

### 19 列分别从哪来

| # | 列 | 数据来源 | 缺的时候怎么办 |
|:--|:--|:--|:--|
| 1 | 商品ID | URL / rawData | 总是有 |
| 2 | 商品名称 | h1 / rawData | 总是有 |
| 3 | 品牌 | rawData.brandName / 属性里的「品牌」 | 有些商品本来就没品牌 |
| 4 | 分类 | 面包屑 / catPath | 总是有 |
| 5 | 库存 | SKU 库存求和 | 无 SKU 时取 item.quantity |
| 6-7 | 团购/单买价格 | 最低价（淘宝无团购概念，两者同价） | 总是有 |
| 8 | 商品主图 | 轮播第一张 | 总是有 |
| 9 | 商品轮播图 | rawData.gallery.pics | 总是有 |
| 10 | **商品详情图** | **desc 接口**（网络钩子）→ 描述区 DOM | **最常见缺项** |
| 11 | **商品描述** | desc 接口 → 描述区文字 | 需要往下滚一屏 |
| 12 | **商品视频** | rawData.gallery.video | 有些商品没视频 |
| 13 | 商品属性 | rawData.attrsVO / 属性表 | 总是有 |
| 14-19 | SKU 六列 | rawData.skuCore.sku2info | 无规格商品本来就没有 |

### 详情图 / 描述为什么容易缺

这两列**不在 HTML 里**，是页面加载后再去调接口拿的。所以：

1. **必须往下滚到「宝贝详情」那一段**，让接口真的发出请求
2. 插件里的 `net-hook.js` 会在页面发请求之前先挂上钩子，把响应抄下来
3. 抄到之后，点「采集本页完整数据」，这两列就有了

**没滚到位 = 这两列空**，这是设计如此，不是 bug。

## 九、自检

```powershell
F:\pyenvs\douyin\Scripts\python.exe _自检.py        # 采集/导出 40 项
F:\pyenvs\douyin\Scripts\python.exe _自检_分析.py   # 智能分析 23 项
F:\pyenvs\douyin\Scripts\python.exe _自检_HTTP.py   # 走 HTTP 验接口

```

| 脚本 | 项数 | 覆盖 |
|:--|:--:|:--|
| `_自检.py` | 40 | 粗采入库 → 细采补全（且粗采不覆盖细采）→ 同款聚类找源头 → CSV 格式 → 价格闸门反例 → 去重 |
