# 4.1 · 主图 AI 重做 —— 接进上货台的说明

> 版本：上货台 v0.5.3 ｜ 位置：第 4 步「检测打码」之后、第 5 步「出表」之前 ｜ 2026-10-24

## 一、为什么单开一页，而不是塞进第 4 步

| | 第 4 步 | 4.1 这一页 |
|:--|:--|:--|
| 改什么 | **同一张图上**的违规字/字块 | **整张主图重做**（白底/换景/清促销/重绘） |
| 产物 | 还是那张图，涂掉/修补后的版本 | **另一张候选图** |
| 谁决定 | 词库命中即处理 | 必须人工看图确认 |
| 账怎么记 | 打码日志 | 每次调用单独记费用与资产 |

两类产物性质不同，混一页会把「消除违规」和「换主图」的审计记录、失败回退、费用台账搅在一起。

## 二、引擎在哪、有没有重写

**没有重写。** 本页只做三件事：选图、跑、确认。

- 引擎：`taobao-picker\image_lab\`（engine / providers / schema，v3.4 那套）
- 调用方式：**运行时从源码目录导入**（`sys.path` 插到最前），不是复制代码，也不是另起服务
- 库：`taobao-picker\data\image_lab.db`（它自己的库）。代码里有**路径断言**：一旦发现库指向别处（例如被打包进 `_internal` 的那份空库），直接报错并停用，不会悄悄记到空库里去

## 三、三条硬约束怎么落地的（写进代码，不是写在注释里）

1. **原图永不覆盖** —— AI 产物是 `image_assets` 里新的一条，`is_original=0`，`parent_asset_id` 指回原图。确认前原始文件一个字节都不动（自测逐张比过 sha256）
2. **未确认不进发布** —— 出表读的是 `v3_image.current_local_path`；只有在本页点「✓ 确认换成这张」才会改它。不确认就一直只是候选
3. **每次替换留旧值** —— 改指针**之前**先写 `lab_writeback`（4.1 自有表，不动 v3 结构）。台账写失败会把指针改回去，宁可这次白做也不留无记录的替换。「↶ 退回上一版」按台账恢复

## 六、打包注意（踩过的坑）

exe 里 4.1 曾报 `ModuleNotFoundError: No module named 'uuid'` —— 因为 `image_lab` 是**运行时动态导入**的，PyInstaller 静态分析看不到它的依赖。

修法（已固化进 `打包.cmd`）：

```
--paths "%~dp0..\taobao-picker"        # 让 PyInstaller 分析到 image_lab，自动收依赖
--hidden-import uuid / urllib.request / urllib.error / urllib.parse
--hidden-import http.client / email.parser / hashlib / tempfile / secrets / mimetypes / ssl
--hidden-import PIL / PIL.Image / PIL.ImageDraw / PIL.ImageFont
```

**改了代码必须双击 `打包.cmd` 重打一次**，否则跑的还是旧逻辑。
