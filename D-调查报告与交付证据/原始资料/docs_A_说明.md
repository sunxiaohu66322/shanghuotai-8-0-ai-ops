# 上货台 · v0.5.0

**一个窗口跑完整条上货流水线**。桌面程序（Python 3.13 + PyQt6），不是网页套壳，**全程不开浏览器**。

---

| 方式 | 位置 |
|:--|:--|
| **桌面快捷方式**（推荐） | 桌面上的「上货台」图标 |
| 源码直接跑 | `F:\pyenvs\douyin\Scripts\python.exe run.pyw` |

## 二、底座是什么（主人在问的那件事）

**Python 3.13 + PyQt6** —— 和「本地服务控制中心」**完全同一套底座**，原生 Win32 窗口。

| 项 | 事实 |
|:--|:--|
| 是网页套壳吗 | ❌ 不是。没有 WebView、没有 Electron、没有内嵌浏览器 |
| 会跳浏览器吗 | **只有 1 处**：两张结果表的「▸ 打开」格 / 双击行 —— 点它才在浏览器打开那个商品页。启动、采集、精筛、打码、出表**全程不跳**（自测逐文件扫过，并断言这 1 处必须在点击处理函数里） |
| 为什么之前会跳 | 「本地服务控制中心」的**快速访问页**本来就设计成"点一下在浏览器里打开服务"。那是那个程序的功能，不是底座的问题，这版**根本没有这一页** |
| 和插件怎么配合 | 采集走浏览器调试口（CDP），三种情况：**同关键词的搜索页已开 → 直读，不动你的页面**；**开着别的淘宝搜索页 → 把那一页导航过去**；**一个都没有 → 新开一个标签去搜**（测试标签用完即关）。**不点商品、不进详情页**；取图走本地库与图床 |

## v0.1.2（2026-10-22）多关键词 + 每个关键词一个结果页签

### 关键词可以一次输多个
输入框里用 **逗号 / 中文逗号 / 顿号 / 分号** 都行：

```
透明帐篷，露营灯, 户外椅；折叠床
```

会按顺序逐个采，每个关键词之间自动歇 3 秒左右（带随机抖动）。

### 每个关键词一个独立页签，缓存在本机
采完一个关键词，主区域就多一个页签，标着「关键词  保留数/剔除数」。

- 内容存在 	aobao-picker\采集结果\会话\<时间>_<关键词>.json，索引在 _index.json
- **关掉软件不会丢**，下次打开在底部「历史页签」下拉里还能载入
- **页签上的 × 就是删除它的缓存**（会先问一次）
- 底部还有「删除缓存」按钮，删的是下拉里选的那一条
- 已经导出过的 CSV **不受影响** —— 删的只是软件里的这份缓存

### 翻页修好了（之前是错的）
旧版翻页是「改 URL 里的 page 参数再重新加载」—— 淘宝搜索页是前端应用，不认这个参数，
重新加载后又从第 1 页开始，所以选 2 页 = 刷新两次 = 还是第 1 页。

现在改成**真的去点页面右下角那个「下一页」按钮**，并且：
- 翻页前先停「翻页间隔」（默认 4.5 秒，可调，带 ±25% 随机抖动）
- 翻完不是死等，而是**等到页码真变了、卡片真回填了**才继续
- 采到的页数会写在日志里：「想采 N 页，实际采到 M 页」

### ⚠ 淘宝第 2 页起要求登录
实测：未登录时点第 2 页，淘宝会弹一个迷你登录框，卡片一张都不回填。
程序会**直接停下并说明原因**，不会把第 1 页重复采 N 遍。

要翻页，请先在这个浏览器里登录淘宝；只想采第 1 页时，页数填 1 就行。

### 导出改成「导出当前页签」
采完不落盘。你翻页签、逐行核对，确认哪个关键词的结果可用，就切到那个页签点导出。
其他页签不受影响。

## v0.1.6（2026-10-22）停止按钮 + 治「翻页等半天没动静」

### 一、为什么翻页会「等半天没动静」（实测根因，两层）

```
① 连接不复用：humanize.send() 每发一个 CDP 命令就 websocket.create_connection 一条新连接。
   而一次真鼠标点击 = 7~14 段移动 + 按下 + 抬起 ⇒ 一次点击要建 ~15 条连接。
   Tabbit 里淘宝页很重，15 次握手里只要有一次不顺，就卡住。

② 命令超时 20 秒：卡住之后不是马上降级，而是白等 20 秒，
   再退回脚本点击 —— 所以一页要等 20~40 秒，看起来像死机。

日志实证（04:45:28）：
   page.turn  via=js-fallback(Connection timed out)     ← 就是它
```

**修法**

- 连接池：同一 ws_url 复用一条连接（失败才重连一次）
- 命令超时 20 → 8 秒；鼠标事件 5 秒
- 鼠标失败过一次，本轮后面直接走脚本点击，不再每页白等

**实测（本地测试页，与生产同一套函数）**

```
click  三次: 0.75s  0.55s  0.60s
scroll 三次: 1.89s  2.32s  1.84s
连发 10 个只读命令: 0.01s
同上但每次都重连:   0.06s      ⇒ 复用快 10.7 倍（真实站点上握手更贵，差距更大）
```

### 二、依赖缺失（已补）

Python313 里**没有 websocket-client** —— 拟人层每个 CDP 调用都会抛
`No module named 'websocket'`。已 `pip install websocket-client`（1.9.2）。

### 三、停止按钮（新）

- 界面「■ 停止」按钮：只有采集中才亮；连点也安全（幂等）
- 后端：`collector.request_stop()` / `clear_stop()` / `stop_requested()` / `collect_running()`
- 检查点：每页开头、翻页等待循环、滚动前、多关键词之间
- **已采到的不会丢**：`collect()` 返回 `stopped=True` + 已采卡片，照常生成页签
- 接口：`POST /api/v3/stop` ｜ `GET /api/v3/status`
- 上货台**直接 import 后端模块**（不走 HTTP），点停止在同一进程立即生效
- `intake.run_many` 入口会 `clear_stop()` —— 否则上次点过停止、下次开跑会立刻自停

## v0.3.0 · 第二步「数据包导入」重做（2026-10-22）

### 这一版解决的四件事

1. **关键词采集 CSV 能导了**（原来导进去价格、appid、关键词、评论数全丢）
2. **导入记录 = 数据包，可查可删**

4. **第 3 步可以指定数据包**（原来是写死的）

### 数据包是什么

一个「数据包」= **一份导入文件 + 它在库里的全部商品**。
库：`taobao-picker\data\v3.db` 的 `v3_pack` 表（这是「导入记录」）＋ `v3_product` / `v3_image`。

### 支持的格式（按扩展名 + 表头嗅探，不用手选）

| 格式 | 说明 |
|:--|:--|
| **关键词采集 CSV** | 商品ID/标题/到手价/销量/销量原文/评论数/好评数/差评数/有图评论数/店铺/店铺已售/appid/关键词/主图 —— **14 列全部认得出** |
| 微信小店 19 列 CSV | 老格式，照旧 |
| 小猪 58 列 CSV | 照旧 |
| rawData JSON / items JSON | 照旧 |

### 列映射这一版补的（`v3\importer.py`）

```
到手价 券后价 实付价   → price_min        （原来只认 价格/售价，到手价被丢掉）
销量原文               → sales_text
appid 小程序appid      → appid            （微信小程序 ID，后面靠它定位商品）
关键词 搜索词          → keyword
评论数 好评数 差评数 有图评论数 店铺已售   → 各自字段
```

另外 `original_payload` 现在**连认不出的列也一起存**（`_extra`），不再静默丢弃。

### 转换状态（第 3 步的闸门）

| 状态 | 含义 | 能进第 3 步 |
|:--|:--|:--:|
| ⏳ pending | 已登记、还没转 | ✘ |
| … converting | 正在转 | ✘ |
| ✅ converted | 转成功，且有商品 | ✔（还要有图） |
| ⚠ empty | 文件里 0 个可用商品（标题列没认对？） | ✘ |
| ✗ error | 转换报错，错误原文写进 `error` | ✘ |

**「可进第 3 步」的判据是真数字**：`商品数 > 0` **且** `图片数 > 0`。不满足会把原因写在 `reasons` 里（例如「没有图片：主图列是空的或不是 http 网址」）。

### 删除

- 删一个包 = 删 `v3_pack` 那条 + 该包全部商品 + 它们的图片 / 标题候选 / 任务记录
- **源文件不动**；想恢复 = 同一个文件再导一次
- 界面会先弹确认框，写清要删多少商品、多少图

### 第 3 步现在怎么走（固定流程）


### 固化了哪些规则（每条都是实测踩出来的，改之前先想清楚）

| # | 规则 | 为什么 |
|:--|:--|:--|
| 1 | 表头在第 **2** 行，A..P 16 列，与 `UPLOAD_DEMO1.xlsx` 第 2 行**逐字一致** | 小猪按表头识别字段，不靠列序；第 1 行是 A1:N1 合并的红色说明 |

| 7 | 源 `spec` 常是长度 1 的整串，按 `【胡桃色】xxx` 前缀 / `a / b` 斜杠拆维度 | 采集端只给整串，维度得自己拆 |
