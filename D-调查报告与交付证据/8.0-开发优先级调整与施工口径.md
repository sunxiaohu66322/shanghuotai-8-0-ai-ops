## 一、两条业务彻底分开（硬口径，最高优先）

| 维度 | ① 商品详情视频 | ② 内容视频挂商品 |
|:--|:--|:--|
| 是什么 | 商品详情页里、轮播图位置那个视频字段 | 往抖音/视频号发一条作品，作品上挂商品链接 |
| 落点 | 商品对象（微信 `head_videos` / 抖店主图视频） | 内容作品（视频号作品 / 抖音短视频） |
| **价值定位** | **改善商品展示与转化** | **发布时关联商品 = 唯一额外流量入口** |
| **禁止口径** | **不得宣称能直接增加商城搜索曝光** | 不得宣称"发布后能补挂商品" |
| 账号 | 现有微信 2 店 appid / 现有抖店后台 | 现有抖店官方账号 / 现有视频号（先核实现有） |
| 接口 | 微信有 API；抖店暂无本机 API 接入 | 发布/挂商品两平台均无可用 API |
| 人工量 | 近全自动 | 最后发布确认必须人点 |
| 关联动作 | 无（视频本身就是商品素材） | **必须在发布同一次操作里完成** |

> 两条链路账号、接口、权限、验收全不一样，**排期、页签、任务记录都必须分开建**，不许合并成一个"视频任务"。

## 二、八条决策口径逐条落地

| # | 主人口径 | 落成规则 | 验收判据 |
|:--|:--|:--|:--|
| 1 | 两条业务独立、必须分开 | 任务队列分两类 `detail_video` / `content_video`；页签两个分区；统计分开计数 | 代码/页签里两类任务不共用一条状态机 |
| 2 | 详情视频只改善展示转化，不宣称搜索曝光 | 所有文案、报告、页签标签只写"商品展示/转化"，删去"提升搜索曝光/搜索加权"类表述 | 全文检索无"曝光提升"绑定到详情视频 |
| 3 | 内容视频发布时关联商品 = 额外流量入口 | 关联动作与发布绑定在一次操作；自动化止于发布确认前 | 单品验证里作品可见且挂了商品 |
| 4 | 不建账号矩阵，优先现有抖店官方账号 + 现有视频号 | 顺序固定：**先核实现有账号绑定与带货权益 → 现有能用就用 → 确实缺才补最小 1 个**；不批量注册、不建矩阵 | 账号清单只有"现有 + 至多 1 个补充" |
| 5 | 先选 1 个合法授权视频商品，两平台各跑通 1 次发布+关联+点击核验 | 选品硬条件：视频有合法使用授权、来源可追溯、不带他人水印当原创；抖音 1 条、视频号 1 条，各做「发布 → 发表时挂商品 → 发布后点击商品链接核验」 | 两平台各留一份证据：作品链接 + 挂商品截图 + 点击跳转结果 |
| 6 | E1 12/12 仅本地模拟，必须先做草稿品 E2 真实验证 | **12/12 不得作为上生产依据**；微信侧任何生产动作的前置门 = 用 1 个草稿商品做 E2 | E2 真实后台 `errcode=0` + `product/get` 回读到视频 |
| 7 | 两平台都验证成功后才批量 194 条 | 194 条历史视频批量排在 P1 之后；P1 未全绿不许起批量 | 批量任务启动条件 = P0 + P1 全绿记录存在 |
| 8 | 只在现有 8.0 加简单商品视频任务页签，不新建独立运营系统 | 不建独立运营引擎、不建 9192 服务、不建 `ops_*` 表、不做独立账号矩阵 | 新增代码只落在现有 8.0 的一个页签 + 其任务记录 |

**明确不做**：直播、达人矩阵、人工拍摄、复杂视频制作流程、独立运营系统、账号矩阵。

## 四、新的施工顺序（P0 → P2；每步带验收判据）

### P0 · 微信商品详情视频（最高优先，现有账号、零新增）
1. **P0-1 E2 草稿品真实验证**：E1 副本 4 接口迁到生产 `wxapi.py` → 1 个草稿商品真实提交 `head_videos` → `product/get` 回读。
   - 验收：真实后台 `errcode=0` + 回读有视频 + 记录真实字段名/接口参数/临时链时效。
   - **这是 12/12 之后唯一的晋级门**；未过不许进 P0-2，更不许碰 194 条。
   - 前置：改生产代码、碰草稿商品 → 需主人一句开工指令（本轮只读边界内不执行）。
2. **P0-2 单品端到端**：选 1 个有合法使用授权的视频商品，跑通「采集视频下载 → 4 步上传 → `head_videos` 写入 → 回读」。
   - 验收：商品详情页能看到视频。

### P1 · 内容视频单品验证（两平台各 1 条，人工只点最后确认）
3. **P1-0 核实现有账号**：现有抖店官方账号绑定状态 + 带货权益；现有视频号与小店关联状态 + 短视频商品分享权益。本机查不到，主人后台看一眼（只读，不改动）。
4. **P1-1 抖音 1 条**：素材准备 → 发布页预填 → 发表时挂商品 → **人工点发布** → 点击商品链接核验跳转。
5. **P1-2 视频号 1 条**：同上。
   - 验收：两平台各 1 份证据（作品链接 + 挂商品 + 点击跳转结果）。**任一平台未通过，不进 P2。**

### P2 · 验证成功后才做
6. 现有 8.0 增加「商品视频任务」简单页签（两类任务分区、状态、证据链接）。
7. 两平台 P1 全绿后，才考虑 194 条历史视频批量（仍按 ① 详情视频 / ② 内容视频 分两条队列）。

### P3 · 暂缓（登记不做）
独立运营系统 / 9192 / `ops_*` 表 / 账号矩阵 / 直播 / 达人矩阵 / 复杂视频制作 / 人工拍摄。

## 五、自动化边界（对齐目标「人工只负责最后发布确认」）

**可自动化**
- 本地：采集视频下载、格式/时长/授权标记检查、按商品 ID 归档、临时链即时用不入库。
- 微信商品详情视频：4 步上传 + `head_videos` 写入 + `product/get` 回读（E2 通过后）。
- 内容视频：素材准备、文案/封面准备、发布页表单预填、选品入橱窗准备、跳到发布页、发布结果核对。

**人工（不可省）**
- 账号绑定与带货权益首次开通/扫码。
- 内容视频的**最后发布确认按钮**。
- 发布后**点击商品链接核验**（P1 阶段的见证动作）。

> 比原报告更进一步：自动化覆盖到发布确认之前的所有环节；但**不做无人值守发布、不做发布后补挂**。
