## 2. 实际完成

### 2.1 S1-01 页内 F5 —— 已验收（后端 0 改业务逻辑，界面 1 处改造，共享库 1 处快速路径）

**改前（正式 exe，04:01 实测）**：页内 F5 **941.6 ms**；切 2.5 = 93.5 ms。

**分段定位（先量再说，不猜）**：

```
库层（Library，只读）         products 5.9–6.7ms · local_images_map 7.4–8.5ms
                              facets 2.8–3.3ms · stats 4.8–5.6ms
                              审核进度 5 条 SQL 2.7ms       → 库一共 ≈ 24ms
控件层（WallPage.reload 分段） _fill_tree 3.3–4.6ms · _reset_cards 16–37ms
                              _update_sel 2.5–4.1ms
                              **_refresh_review 215–248ms**  ← 真凶
存储层（store.init）          connect 5.0–5.4ms · **init 72.5–77.7ms**（executescript 仅 0.4ms，
                              MIGRATIONS 0.2ms，98% 是那次写事务的 WAL 提交）
```

**根因（两条，都在同一处汇合）**：
`bridge._wrap()` → `flow.conn()` → `store.connect()` + **`store.init()`**。
`init()` 每次都跑 `executescript(SCHEMA_SQL)` + 逐表 `PRAGMA table_info` + 4 条
`INSERT OR IGNORE/REPLACE` + `commit()`。而 2.5 每次 F5 都会调 `_refresh_review()`
→ `v3_review_progress()` → 走这条链，**在 GUI 线程里固定烧掉 215–248ms**；
整个 `reload()` 因此接近 1 秒。

**修法**：

| 层 | 改动 | 位置 |
|:--|:--|:--|
| 共享库 | `store.init()` 增加进程内快速路径：`PRAGMA database_list` 取真实库路径 + `user_version>=300` + 本进程已完整迁移过 → **直接返回，不写库不提交**；换库/升级版本/换进程照常全跑 | `taobao-picker\server\v3\store.py` |
| 界面 | `_refresh_review()` 改为后台线程 `_RevWorker(QThread)`；带「代数」保护（seq），旧结果只丢不写；在途时只记 `_rev_pending`，回来补跑一次；`closeEvent` 逐个 `wait(3000)` 收线程 | `上货台\app\ui\wall.py` |

**改后（同一台机、同一份库、同一条代码路径）**：

```
正式 exe（重打包 04:17:34，04:24:45 实测）:
  页内 F5 重新查询（全量条件） : 941.6 ms → **87.9 ms**   （-90.7%）
  切到 2.5 页签                : 93.5 ms → 86.1 ms
  点开详情（首次解码）         : 444.4 → 115.2 ms（源码运行时含冷启动解码，波动）
  再点同一件（命中缓存）       : 70.3 → 91.1 ms
  滚动加载 +60 件              : 17.5 → 19.9 ms
  切列表视图                   : 25.0 → 28.1 ms
  page.perf(): reload 52.9 ms / detail 45.6 ms
源码直接运行（04:14:49）:
  页内 F5 = 65.5 ms · 切 2.5 = 148.6 ms · 详情首次 444.4 ms
审核进度在主线程占用         : 215–248 ms → **0.18 ms**
offscreen 离线复测           : 275–464 ms → 56–85 ms（中位 56）
```

### 2.3 S1-03 安全取消 —— 未完成（如实）

- **已有**：`v3\dlcenter.py` 具备 `pause/resume/stop`，用 `threading.Event` 控制，任务状态机含

## 6. 用户能看到的变化

- **按 F5 刷新 2.5 商品库**：从"按下去等将近一秒"变成"基本立刻回来"（实测 65.5ms）。
  右下角那行"本次查询 xx ms"现在反映的是真实查询耗时，不再把审核进度算进去。
- **删除数据包**：删完之后，左树里**不会再留下那个包的空壳节点**（以前会，点进去还有货）。
- **回收站还原**：还原回来的商品**带图和 OCR**，不再是"有商品没图片"的空壳；
  从旧版本存进回收站的老记录会明说"OCR 只有摘要，没逐条恢复"，不假装。
- **回收站为空时点清空**：会直接说"回收站已经是空的"，不再像没反应。
