## 1. 🔴 新旧架构的唯一硬冲突（必须先解决）

| | 旧 P0（dev） | 新架构（本轮指令 §三） |
|:--|:--|:--|
| 数据落点 | **一张库**：把 12 张 `ops_*` 表 CREATE 进 `v3_dev.db` | **两张库**：独立 `ops.db` 写；`v3.db` 商品主库只读 |
| 证据 | `config.py:31` 默认 `v3_dev.db`；`migrate.py:2` 「把 ops_* 表加进 v3.db」 | §三「ops.db 独立、v3.db 默认只读、不得直接修改商品主库」 |
| 结论 | **不能直接照搬**：直接跑旧 migrate 会往生产 v3.db 写表（红线） | 收编时必须改造 |

**已实测的解法（[事实]）**：`ops.db` 主连接（可写）→ `ATTACH DATABASE 'file:<v3.db>?mode=ro' AS vsrc` → `CREATE TEMP VIEW v3_product/v3_image/v3_upload_status AS SELECT * FROM vsrc.<表>`。
- 旧 `store.py` 里查裸表名 `v3_product` 的 SQL **一行不用改**（temp 视图优先命中）；
- `UPDATE v3_product` 实测被拦：`OperationalError: cannot modify v3_product because it is a view`；
- `ops_task` 写主库实测 OK；`PRAGMA quick_check` 落在小库 ops.db（更快）；`sqlite_master` 不含 temp 视图，不污染 `table_counts()`。
