## 四、每期的验收方式（不许用「接口 200」当验收）

沿用本项目已经在用的三条硬判据（都是踩过坑后立的）：

1. **数据自证**：库里的行数/状态变化，不是命令返回值。`[源码确认]` 本项目已立此规（`01_架构.md` §五、`02_现状与边界.md` 的「生产库 mtime 未变」式验证）。
2. **界面真点**：7.0 页签要用 ego lite 像客户一样点一遍（铁律 21），**不许只看单测全绿**。
3. **不覆盖原片**：生成前后对原片算 sha256，必须一致；不一致即判失败。

## 六、时间与成本的现实估计（不许乐观报数）

- **总工期**：8–12 周（按每周 ≥20 小时有效投入估）。**不承诺具体完工日**，只承诺每期有可验收产物。
- **最大不确定性**：抖店侧没有 API → 所有抖音运营数据与发布都是浏览器流程，**稳定性和速度都受平台页面变化影响**；这部分返工风险最高。
- **最大成本项**：视频渲染（FFmpeg 本机有 `[本机实测]` `F:\视频下载器\ffmpeg-9.0.1-essentials_build\bin\ffmpeg.exe`）+ TTS 配音（需外部服务，产生费用，**须主人批准**）。
- **不建议做的事**：① 为「运营自动化」重写 1–6.0；② 建第二个库；③ 把运营逻辑塞进 `bridge.py`（它已 265KB / 351 个顶层函数 `[本机实测]`，再加会失控）。
