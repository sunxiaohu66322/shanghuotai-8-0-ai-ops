## 判据与用法

```
python engine/build_whitelist.py              # 重建白名单（全店商品变化后重跑）
python engine/prefilter.py 候选.json          # 初筛：输出 PASS / PROBE / DROP
python engine/prefilter.py --selftest         # 自测
```

### 三档结论

| 结论 | 含义 | 后续 |
|:--|:--|:--|
| **PASS** | cid 在白名单 + 无高危价格问题 | 直接建品 |
| **PROBE** | cid 不在白名单 / 无 cid / 价格高危 | 建品时读系统返回的 `status`（0 可建 / 2 需开通）再定 |
| **DROP** | 一级类目不在经营范围，或标题命中非经营品类强特征词 | 初筛即剔，不浪费建品动作 |

### 已实测的边界

- 全店 3846 件反向验证：**PASS 3667 / PROBE 179 / DROP 0** —— 零误杀（它们本就都是真实存在的商品）
- 179 件 PROBE 全部由价格高危触发（划线价/售价倍率过高），与价格防线计算器的 157 件结论一致
- 自测 4/4：白名单内→PASS、无 cid→PROBE、手机充电器→DROP、白名单内+12.8 倍划线价→PROBE

## 需要注意的否定条件

- **不在白名单 ≠ 禁止**：只是「没在本店建过」，需建品时探 `status`，不能据此判死
- **标题关键词判一级只是粗筛**，只用于剔掉明显不属于的品类（手机/美妆/母婴/工业品），不用于定类目
- 用户口述要单独出钱的细分类（皮艺沙发/皮艺床/儿童组合柜）在表里已标 `paid_hint`，建前须确认
- 白名单会随商品变化而变：**每次精铺新类目成功后，重跑 build_whitelist.py 扩容**
