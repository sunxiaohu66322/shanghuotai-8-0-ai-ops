## 1. 已经实测到的事实（每条都可复现）

### 1.1 整站是「抖店服务市场」的一个应用，不是独立站点

```

  303  Location: https://fuwu.jinritemai.com/authorize?service_id=21236&redi=close
```

  → 所谓「登录」，就是**抖店商家账号授权**（OAuth），没有抖店店铺就没有别的入口。

### 1.2 目标页与它下面的一切都被 302 挡回登录

```
GET /c/excelCopyItem/dyForm     → 302  Location: /login
GET /c/                          → 302  Location: /login
GET /c/index.html                → 302  Location: /login
GET /c/static/js/main.js         → 302  Location: /login   ← 连 JS 静态资源路径都挡
```

## 3. 由模板约束反推的机制（**全部是 `[推断]`，不是观察到的**）

先立一条**硬约束**，它把可能的设计空间压得很小：

> `01-模板结构.md` 已证明：模板只有 `规格1/规格2/规格3` 三个**位置槽**，**没有任何一列装规格的名字**（没有「颜色分类」「尺码」这种维度名），而 `SKU规格名称` 是各槽取值用半角空格拼出来的（`G3='HP31054 M' = 规格1+' '+规格2`）。

在这个约束下，任何能产出该模板的工具都**必然**要做这四件事：

| # | 必然步骤 | 依据（从模板反推） | 置信度 |
|:--|:--|:--|:--|
| 1 | **按源商品的规格数组做「按位映射」**：`规格N = 源 sku.spec[N-1]` | 因为模板三个槽没有名字，工具无法按「颜色/尺码」语义去找，只能按原数组下标塞进去。样本 `规格1` 4 行恒定 `HP31054`、`规格2` 变化 M/L/XL/XXL —— 这正是**源商品 spec 数组第 1 位是货号、第 2 位是尺码**时的样子 | `[推断]` 高 |
| 2 | **`SKU规格名称` 由各槽取值 join(' ') 生成，不是独立字段** | `G = H+' '+I` 四行全成立；模板里也没有别的来源 | `[推断]` 高（几乎等于观测） |
| 3 | **维度的「名字」在导出时被丢弃** | 模板没有列能装它；`SKU规格名称` 里也只有值没有名（`HP31054 M` 不含「颜色」「尺码」字样） | `[推断]` 高 |
| 4 | **笛卡尔积 + 缺组合**：工具必须能只写「实际存在的 SKU 行」 | 样本两个商品各 4 行 = 2 维各 4 值/4 值… 但真正能证明这一点的样本**不存在**（样本没有缺组合的商品），所以「缺组合怎么处理」**只能进 04** | `[推断]` 中 |

**图片处理（也是推断）**：样本 `D3/N3/O3` 全是 `https://1832850322.v.123pan.cn/...` 的 123 网盘直链。
→ `[推断]` 该工具（或造这个示例的人）**先把商品图上传到公网图床/网盘，再把 URL 写进单元格**；导出的 Excel 本身不带图。

**输出形态**：`[推断]` 前端生成 —— 模板 `Application` 标着 `Openpyxl 3.1.5` 而 `lastModifiedBy` 是 WPS 里的人名，说明这个特定样本是**本地脚本生成的**，不是服务端直出；但这只说明这一份文件，说明不了小猪的实现。

## 4. 对我们的采集数据意味着什么（这条是本任务的实际落点）

我们的 `plan-*.json` 里 `skus[].spec` 是 **长度 1 的数组**，整串扁平名（`527【实木-可移动-翻盖可调节】胡桃色（长40）`）全塞在 `[0]`。
→ **上面第 1 条「按位映射」对我们完全不适用**（映射进去就变成 `规格1 = 整串名字`）。

所以我们的转换必须**自己做拆分**，把一串名字还原成「颜色分类 × 尺寸」两维，再按位置写进 `规格1/规格2`。
拆分算法与实测结果见 `03-转换方案.md` 第 3 节（已用 plan-1436 跑通：`颜色分类(3) × 尺寸(2)`，缺失组合 1 个 = `黑色/长40`，与任务书给的例子一致）。
