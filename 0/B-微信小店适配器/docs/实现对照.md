## 四档口径

- **可用（real）**：调官方 `channels/ec` 接口真写。改价格 / 改库存 / 上下架 / 改标题 / 改标题前缀 / 删除商品 等；另有只读页面（类目、订单、运费模板、优惠券、商品列表、云库、诊断、导出、导入解析、任务记录、快速修改、新建上货）。
- **补丁（patch）**：`POST /api/patch`，白名单字段 `title / sub_title / weight / spu_code`，走 `product/update` 最小改动，逐件返回错误码。当前：改短标题、改货号、改重量。
- **只读（read）**：数据能读、写入未接。恢复回收站、改运费模板、优惠券。
- **壳（shell）**：菜单、页面骨架、真实商品表格都在，动作按钮置灰，并写明「接入还缺什么」。32 个。

## 与原版的差异（刻意如此）

1. **没有「店铺管理」页**：原版那是 ISV 管多商户用的，自研只有一个店。
2. **多店关联保留菜单但标注不适用**：微信官方没有「跨店绑定」这类能力，原版是自家授权码。
3. **云库改为本机备份**：原版存它服务器（`yunku/*`），本地换成 `data/yunku/*.json`，先备份再批量改，改坏可回滚。
4. **商品诊断用本地规则**：无标题 / 标题超 60 / 无主图 / 无 SKU / 价格 0 / 库存 0 / 无类目。平台合规质检需官方接口。
5. **导出为通用 CSV**：`data/exports/exp-*.csv`（UTF-8 BOM，Excel 直开）。微信 19 列模板是另一条路（导入侧已能解析列）。

## 怎么加一个页面

1. `web/menu.js` 加叶项：`{ key:'/xxx', title:'xxx', page:'xxx' }` 或 `{ ..., act:'xxx' }`（走批量工作台）。
2. `web/pages.js` 里加 `P.xxx = (root, leaf) => {...}`；批量动作用 `ACT` 注册表加一项（`kind: batch|patch|delete`）。
3. 需要后端就在 `app.py` 的 `_api_get/_api_post` 加一条，前端 `U.get/U.post` 调。
